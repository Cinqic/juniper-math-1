# Juniper Math 1 — exact Phase 0 environment lock.
#
# WHY THIS FILE EXISTS
# The Phase 0 review candidate declared only compatibility ranges
# (torch>=2.2,<3.0, ruff>=0.6,<1.0, ...). Ranges are correct package metadata
# but they are not a reproducible environment: a fresh install months later
# could resolve a materially different ruff (whose formatter output changes
# across minor releases) or mypy, and `ruff format --check .` / `mypy` are
# Phase 0 gates. See reports/OPUS5_PHASE0_REVIEW.md (F-03).
#
# WHAT IT PINS
# Every package present in the validated Phase 0 environment, at the exact
# version that passed the full Phase 0 gate — including transitive
# dependencies, so resolution is deterministic rather than re-solved.
#
# WHAT IT DOES NOT PIN
# The system layer. This file reproduces the PYTHON layer only. It does NOT
# reproduce the Linux kernel, the NVIDIA driver, the CUDA driver stack, or
# firmware. Those are system prerequisites documented in docs/ENVIRONMENT.md
# and docs/RECOVERY.md and must be installed separately.
#
# PLATFORM SCOPE
# Generated on Linux x86_64 with CUDA-enabled PyTorch (nvidia-* wheels are
# present for that reason). Python 3.12 only — numpy 2.5.2 requires >=3.12,
# which is why pyproject.toml declares >=3.12,<3.13.
#
# USAGE
#   python3 -m venv .venv
#   source .venv/bin/activate
#   pip install --upgrade pip
#   pip install -r requirements-lock.txt
#   pip install -e . --no-deps
#
# REGENERATING (only after a deliberate, tested dependency change)
#   pip freeze --exclude-editable | sort > requirements-lock.txt
#   # then re-add this header, re-run the full Phase 0 gate, and update
#   # manifests/licenses.yaml + manifests/artifacts.yaml as needed.
